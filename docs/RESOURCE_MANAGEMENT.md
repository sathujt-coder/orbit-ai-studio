# P5.3 — Resource Management
Open /resources.html (deployment operator only). The backend exposes Linux /proc RAM/RSS and cgroup v2 effective RAM headroom including ancestors, CPU affinity/quota, process CPU sampling, optional NVIDIA GPU/VRAM telemetry. Unknown metrics remain null. CPU percentage is backend process utilization relative to its effective cores, not Ollama process utilization. Darwin/Windows memory and non-NVIDIA GPU telemetry are not implemented; observe mode is safe there, enforce mode fails closed when memory telemetry is unknown. No remote GPU claims.

Startup environment: ORBIT_RESOURCE_MODE=observe (default) or enforce; ORBIT_RESOURCE_MIN_FREE_MIB=128; ORBIT_RESOURCE_MAX_MEMORY_PERCENT=95. In observe mode record would-block events but continue. Enforce mode checks backend memory headroom/pressure before every instrumented real chat request, blocks with a fixed diagnostic before recording a token/cost attempt, never changes provider or retries. Process-local admission counters reset on restart. This does not reserve memory or prevent concurrent callers racing; P5.4/P5.5 address scheduling/concurrency. Backend cgroup limits may not cover Ollama; for model service use its own container memory/cpu bounds, OLLAMA_NUM_PARALLEL and OLLAMA_MAX_LOADED_MODELS. No automatic model unload or host changes. Resource guard is opt-in, not an OOM guarantee.

An explicit CSRF-protected operator request reads /api/ps only for currently configured loopback Ollama endpoints. It exposes resident size, VRAM and context when reported. Does not call remote URLs, pull/load models or generate tokens. Local endpoint might be a separate container. No arbitrary command execution, Docker socket exposure or new dependencies in backend. Optional fixed nvidia-smi subprocess has short timeout, output fields only, cached five seconds.

CI actual airgapped Ollama service has 6 GiB RAM/no extra swap and 2 CPUs; one loaded model and one parallel request. Offline workflow uses enforced backend resource admission, validates real per-round counts and loaded model metadata, then captures Docker inspect/stats and OOM state. Stats are a final sample, not peak usage or continuous resource stress testing. GPU hardware CI is not available/verified. Existing TLS/proxy backend 512 MiB / 2 CPU limits remain unchanged. No production approval; P5.8 adds continuous monitoring, P5.9 sustained load.

The cgroup reader treats missing leaf memory controller data as unknown, including a private namespace root. The operator model-status route has its own audit action, separate from general model listing. Tests cover actual local HTTP metadata and mocked NVIDIA output; hardware GPU behavior remains unverified.
