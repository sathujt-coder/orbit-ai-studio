# Offline inference: Codex Cloud and reproducible CI

This is an actual Ollama inference test, not a mock. Two compact local models: qwen2.5-coder:1.5b and qwen2.5:1.5b. Download stage requires internet. Inference uses only localhost and locally stored weights; no OpenAI API key. Small models may produce invalid JSON or fail peer review. Report distinguishes connectivity, actual calls, review gate, and unverified sandbox/production status. It never executes generated code or publishes it.

## Codex Cloud
Create/publish a cloud environment for this branch. Install Ollama using the official Linux installation instructions (https://ollama.com/download/linux), then execute `bash tools/setup_offline_models.sh` in the setup phase with network allowed. Ensure the model cache persists into the task, enough CPU/RAM/disk exist, and localhost processes are permitted. Disable external agent network for the inference task if supported. Execute `bash tools/run_offline_models.sh /tmp/orbit-offline-report.json`. Inspect the JSON and report limitations. If model files or Ollama are unavailable, report blocker; never substitute fixtures or call an online model. Do not claim network isolation just from the script. Codex Cloud tasks are temporary and not persistent serving infrastructure.

## GitHub CI
Separate workflow downloads models into a temporary volume, stops download container, starts Ollama with Docker --network none, and shares that isolated network namespace with the Python runner. No provider credentials; actual model responses. Models/image tags are resolved at run time; report records actual model digests and runtime version. No generated code execution. A completed review with rejection is a functioning quality gate, not acceptance. A failed generation or connection returns nonzero. Report artifact is redacted and does not retain candidate source; for a real project use run_real_models.py, p4_e2e.py and human-approved Docker verification on a trusted isolated machine. No claims of permanent deployment or Web acceptance.

## Local / remote production configuration
For local Ollama: AI_PROVIDER=ollama AI_BASE_URL=http://127.0.0.1:11434/v1 AI_MODEL_A=qwen2.5-coder:1.5b AI_MODEL_B=qwen2.5:1.5b. Set larger local models based on quality/hardware. For a remote compatible endpoint use AI_PROVIDER=openai-compatible, AI_BASE_URL=https://your-host/v1, model IDs and optional server-side AI_API_KEY. Lane-specific overrides supported. The localhost-only proxy demo network does not have internet egress; configure a deliberate network route for real deployments. Never hardcode credentials.
To retain actual generated proposals in a private local SQLite file for review, run `bash tools/run_offline_models.sh /tmp/orbit-offline-report.json /tmp/orbit-offline.sqlite`. Inspect the job ID in the report, then use `python tools/p4_e2e.py --db /tmp/orbit-offline.sqlite --job-id JOB_ID status`. Only after both reciprocal reviews pass may an operator explicitly run the Docker verification and select a candidate. Do not commit the DB or auto-publish it. If Docker is unavailable in Codex Cloud, report that gate as blocked. Standard inference CI deliberately uploads only redacted JSON.

## P4.6 actual generated code verification
Offline CI now keeps a private temporary SQLite database for the same inference run, verifies both candidate manifests and runs generated unittest tests plus the same ten independently authored arithmetic cases for each candidate. The host checks results, never imports AI source. The independent container mounts only main.py, not the candidate tests. The narrow AST allowlist accepts only the fixed add(a,b) exercise and a small unittest subset; unsupported syntax blocks rather than broadening permissions. Docker uses the resolved image digest, no network, non-root UID, read-only workspace/root, no host credentials/socket, resource/time limits. This is a limited smoke benchmark, not general code safety or Web acceptance. Redacted inference and sandbox JSON are retained; source DB is deleted. No GitHub publication or human signoff is simulated. The original P4.5 run discarded source, so this is a fresh inference run, not verification of the old job. CI confirmation is limited to this synthetic benchmark; real project verification still requires human approval. A rejected model or failed independent contract fails the workflow.
## P4.6.1 bounded repair loop
The prior run c81b18d9dc0f had A independent contract 10/10 but failed generated unittest, and B was blocked by the import policy. The new benchmark spec explicitly matches the existing allowlist. The CI performs at most 3 attempts (initial + 2 repairs), with a fresh private DB and immutable reviewed hashes each round. Only failing lanes regenerate using their own previous source and bounded sandbox diagnostic; passing lanes are reused without a fake generation call. Both lanes receive fresh reciprocal reviews and both run full sandbox checks again. A valid rejected review stops execution, as do infrastructure errors; no retry to force approval. Reports are per round and bind actual model digests and candidate hashes. Diagnostics contain fixed error labels/counts, not raw test output. A strict PASS requires both generated test suites and independent contracts. Prior failed attempts remain in the artifacts; a repaired result is not a first-attempt pass. Only the small synthetic benchmark is covered; no general self-healing or Web production approval.
