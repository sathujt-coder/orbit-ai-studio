# P5.9 — 24/7 Stress Testing
P5.9 has three distinct gates. Passing short CI does NOT establish 24 hours of runtime.
1. Standard CI fixture stress: isolated temporary SQLite, fill actual 200-task queue, reject overflow; kill separate process after two durable claims, recover both as interrupted without replay, drain 198 demo pipeline stages using eight real dispatcher workers. Check one running job per project, attempts, final artifact counts, sampled worker peak, monitoring and SQLite integrity. Then 24-way loopback HTTP fixture waves: two HTTP 503s, circuit blocks 24 requests, one half-open request with 23 simultaneous refusals, recovery, 24 healthy calls and unpriced remote refusal under zero-dollar enforce budget. Check exact HTTP and ledger counts, no slot leaks, no pending records, integrity. Provider fixture is not real inference.
2. Offline CI smoke: 24 real local requests, one per roster ID (12 A, 12 B), production routing and tracked inference admission path, two client slots / four load threads, 12 synthetic projects, zero-dollar enforced policy and unique run IDs. Worker pool idle; this does not run real queue pipeline stages or 24 agents simultaneously. Both local models fixed to pre-pulled qwen2.5-coder:3b and qwen2.5:3b. Periodic monitor must see 24 agents, two models, final released slots and no sampler errors. DB checks actual usage/cost/reservation counts, no unknown or denied calls, closed breakers and integrity. CPU-only Ollama container network none, 6GiB/2 cores, parallel1. Report actual elapsed time, latency percentiles, sampled RSS, all-time ledger. No paid API.
3. Dedicated real 24h soak: run on disposable Linux Docker host, no production DB, explicit confirmation. Docker downloads before isolation; model daemon then network none with same limits. One 24-request wave every 300s for at least 86400s, at least 288 waves (6912 calls), no catch-up burst. Wave must finish within cadence and gap <=310s. Check each wave for slot accounting and RSS growth <=128MiB above first completed wave, workers alive and monitoring no error. Checkpoint JSON atomic per wave; unfinished RUNNING is not PASS. Dedicated client wall timeout 25h. Container sampling every ~30s with actual memory events and fixed container ID; acceptance refuses missing coverage, OOM, restart, failed client duration or missing agents. This is synthetic workload at a controlled cadence, not continuous maximum load, GPU parallelism, full production pipeline load, or proof of indefinite uptime. RSS is sampled and growth threshold is a heuristic, not proof of zero leaks. Database grows during run; SQLite scans may be bottleneck. No automated retries of failed inference; any failure blocks. Hardware, model digests/image versions and host conditions matter. No 24h soak has been run by this PR alone.

Run short fixture: python tools/stress_fixture.py --report /tmp/new-fixture.json --confirm 'RUN ISOLATED STRESS FIXTURE'
Run 24h on isolated dedicated Linux Docker host: bash tools/run_24h_soak.sh /absolute/new/report-directory 'RUN LOCAL 24H SOAK'
Requires Docker, GNU timeout, Python3, disk for model volume, 6GiB inference RAM plus backend and host headroom; no mounted secrets. New report dir only. Local host operator must deliberately launch and retain artifacts. GitHub-hosted PR CI only runs short tests; do not substitute multiple short runs or synthetic timestamps for actual elapsed time. Review soak.json, container-samples.jsonl, acceptance.json, images.txt, models.txt and client.log. Keep evidence from exact accepted commit. The acceptance evaluator tests use synthetic reports only to exercise rejection logic; not real 24h evidence. All changes remain Web-first. Final P5 acceptance requires both short CI and actual soak evidence; further production validation separately.
