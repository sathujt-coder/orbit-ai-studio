# P6.5a — Security evidence consolidation (development only)

## Audit
Existing local session authentication uses scrypt password hashing, hashed session tokens, deny-by-default project RBAC, active-membership authorization and audit events. POST requires origin and CSRF token; session cookie is HttpOnly and SameSite Strict, Secure host cookie in explicit TLS mode. Server rejects unexpected Host/Origin, loopback-only in local mode, sets CSP, no-store, frame denial and nosniff. TLS/proxy smoke and real browser security regressions exist. This does not prove production deployment configuration or in-flight revocation.

Trusted Python assertion runner uses pinned image, no network, readonly root/source, all caps dropped, no-new-privileges, nonroot uid, bounded resources and fixed environment. Git/selection/plan/receipt and P6.4 retest gates are revalidated. The command template check does not inspect a running container; malicious candidate observation forgery remains outside proof. Provider settings mask keys in responses; existing code does not prove absence of committed secrets or safe key storage. Dependency impact is not vulnerability scanning; pinned images and offline locks are not CVE evidence.

## Contract
GET /api/projects/{pid}/engineering/security-evidence/{jid} is scoped read RBAC, rechecked within audited transaction. No POST route, no new DB table or permission. Only exact digests, fixed check/assessment labels and false authorization flags are returned; no file contents, tokens, report results, host paths or exception strings. SECURITY_EVIDENCE_READY means current trusted execution and P6.4 retest evidence plus configured sandbox policy were consolidated. Security gate remains BLOCK; threat model, SAST, dependency vulnerabilities, secret scanning, DAST, production transport and malicious-candidate resistance are NOT_ASSESSED. Unknown/stale/foreign/inconsistent evidence fails closed. Manual refresh in Coding Factory; late responses discarded on project/job change; snapshot label, no automatic authority.

## CI
14 unit regressions; actual planning HTTP owner/viewer reads, foreign project, POST and CSRF denial, unresolved and stale snapshots. Existing isolated Docker lifecycle adds security observations at first closure, stale closure and final closure, without extra execution. Mandatory independent validator reconstructs the three observations from trusted retest receipts and checks HTTP scope/digests. Studio downloads and verifies raw security artifact hash and exact CI identity plus retest link, requires all P6.4 gates and keeps security release blocked. No model, prompt, inference limit, token budget, CI deadlines or production gates changed. No SAST, CVE, secret or DAST scanner is introduced in this increment.

A separate Chromium UI regression uses controlled response fixtures to test READY with security BLOCK, foreign scope rejection, and delayed response after switching jobs. It is not evidence of a real scan. Provider credentials are sourced from deployment environment allowlists and excluded from provider forms; model transport disables redirects and proxy environment inheritance. GitHub credentials remain backend-side; .gitignore excludes .env, private-key extensions, TLS and SQLite files, but does not detect committed secrets or historical leaks. React/TypeScript toolchain versions are pinned or lockfile-installed; deployment and build base tags remain mutable and npm audit is explicitly disabled in the sandbox build. Neither dependency risk nor image CVE risk is assessed here.
