# P6.4e.5d — mandatory trusted Docker retest acceptance

A separate isolated snapshot starts before the deliberately altered assertion in the existing regression lifecycle. Existing unresolved defects are never erased to manufacture a PASS. Five real Docker runs use one unchanged source and assertion inventory: timeout, recovery, recurrence, recovery, fresh passing run. Both occurrences are explicitly repaired; same-run reuse, failed verification and stale digest are rejected, concurrent REOPEN records one receipt and audit, and a fresh passing run invalidates both closed occurrences until explicit revalidation. Every prior receipt is preserved. The live database must be unchanged.

The independent validator recomputes report, priority, registration, repair, view and final gate digests; checks exact lifecycle, scope, runtime, isolation, authorization flags, receipt order and original assertion. The new artifact is mandatory in Studio System Acceptance, downloaded again and checked against the producer digest and run identity. Existing acceptance requirements remain mandatory. Only the aggregate requirements-browser CI job timeout increases from 20 to 30 minutes to accommodate additional actual executions; production deadlines, model, prompts, token budgets and Quality Gates are unchanged. This is development acceptance only, not Real AI or release authorization.
