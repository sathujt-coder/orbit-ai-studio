Operator-only Operations page and GET /api/provider/monitoring, /api/provider/monitoring/history. No new outbound model calls from sampler. Link from main 3D dashboard and Resources. Emergency Control links to existing audited stop/resume workflow; status is read live from control row, sampled alerts may lag. Existing project-specific APIs unchanged. Not an external alert notification system.

Single background sampler starts after worker pool, joins at shutdown. Default 30s (ORBIT_MONITOR_INTERVAL 5–300), history 24h (ORBIT_MONITOR_RETENTION_HOURS 1–168), max 2880 points (ORBIT_MONITOR_MAX_SAMPLES 60–10080); whichever bound hits first. Compact numeric history stored in SQLite, not prompts, credentials or full snapshots. At most 2000 retained alert transition events. Active alert transitions deduped and persisted across restart. Read API does not trigger sampling; latest full snapshot in process memory, historic points durable. Failure retains last successful snapshot, increments counter and marks stale; no sample or >3 intervals also stale. Resource sampling outside DB lock, aggregate/persist under process DB lock. No polling remote endpoints; optional NVIDIA nvidia-smi remains bounded. CPU and RAM backend-visible only; unknown stays null. CPU process sample can be disturbed by separate resource page reads. Queue and ledger aggregate snapshots are not perfectly simultaneous with resource counters. Historical points use sampled timestamp and boot ID, no interpolation across restarts or unknown values. Even index downsampling preserves endpoints, not extremes. No 24h runtime claim.

Dashboard shows 24 registered agents, exact 24h usage per agent, all-time pending ledger count, aggregate task state, queued eligible age, worker pool, active/waiting slots, model usage and latest routing decisions, token/cost coverage, monthly budget holds, breaker counts and recent denials. Configured models labeled defaults; used models are not loaded models. Pending may be interrupted and is not real execution tracing. Alerts include worker unavailable, memory pressure, GPU unknown (info), eligible wait age, stale pending, saturation, circuits, missing usage, reservation overruns, global budget/token caps, recent denial, emergency stop. Defaults queue 300s, pending 600s; no email/push. Status nominal does not prove production readiness. Global spend and historical analytics use existing estimate/ledger semantics. Full monthly ledger scans may grow; not optimized for high-volume deployment.
