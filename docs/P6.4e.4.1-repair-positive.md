# P6.4e.4.1 — Positive repair closure and concurrent writers

The acceptance fixture snapshots a previously passing project into a disposable SQLite/Git copy, preserving the live evidence. One real Docker assertion is subjected to a fixture-only short deadline; a normal run with the same candidate and assertion contract must recover. This demonstrates execution-error recovery, not a source-code change repair. No production timeouts, model, prompt, or gate change.

Two independent SQLite connections compete for assignment, submission and closure using the same expected view digest and BEGIN IMMEDIATE. Each race must produce one immutable receipt, one stale rejection and one allowed repair audit. An independent reviewer verifies the exact original assertion and another reviewer closes explicitly. Recovery alone never changes tracking. The previous changed-assertion negative acceptance remains mandatory.

The additional evidence artifact binds to the previous repair evidence SHA-256 and is required by Studio System Acceptance. No model calls or release authorization.
