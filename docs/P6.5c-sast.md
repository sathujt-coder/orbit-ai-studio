# P6.5c — Static Application Security Testing (development only)

The existing verification_factory.static_scan remains unchanged and mandatory wherever already used. This increment adds a separate deterministic Python AST baseline for the exact selected bound candidate, using validated proposal bytes and the existing Git/source manifest digest. No code is imported, executed, written into the live workspace or sent to an AI or external service. Source sizes follow the existing coding factory bounds; AST walk is capped at 12,000 nodes per file. Rules cover direct/import-aliased dangerous calls, dynamic SQL, insecure TLS, unsafe deserialization, native loading, templates, environment and network access, with fixed requirement IDs. They are conservative findings, not exploit proof; alias assignments, dynamic dispatch, cross-file dataflow and other languages are not fully analyzed. Non-Python non-passive formats block; markdown/text explicitly not scanned; passive-only inventories block. No secret or dependency scan claim. No rule matches is not security clearance.

GET /api/projects/{pid}/engineering/sast/{jid} uses current project read RBAC and transaction, no write route. Returns source/manifest and policy digests, file coverage, rule IDs, severity, line numbers (no source excerpts or secret values). Stale threat evidence cannot grant READY; security gate and all authorization flags remain false/BLOCK. UI refresh clears previous responses on context changes.

CI reuses existing actual Docker fixture's selected proposal; private fixture-only source bytes written mode 0600 to RUNNER_TEMP and deleted by validator; not included in any evidence artifact. Validator reconstructs Git objects and scanner output, compares 3 isolated snapshots and 3 real HTTP snapshots, runs non-executed negative controls. Studio independently binds mandatory engineering-sast-evidence.json to exact CI identity, threat and retest hashes. All previous gates remain mandatory. No model, prompt, token budget, inference limit, CI timeout or production authorization changes.

One controlled-response Chromium regression verifies READY remains security BLOCK, findings rendering, foreign scope rejection and delayed response rejection. The cleanup step also removes private fixture input on CI failure. No raw source is included in the uploaded scan report.
