# P5.6 Smart Model Routing
Default ORBIT_ROUTING_MODE=fixed preserves existing explicitly configured provider pair. Smart mode is opt-in and does not turn demo into live inference. Deployment-owned ORBIT_ROUTING_REGISTRY JSON contains A/B arrays of 1–16 candidates each: id, settings (provider,url,model,timeout,temperature,context_window,max_tokens as Provider Settings), capabilities (general,coding,reasoning,research,design,security,marketing,structured), quality (0–100), min_ram_mib,min_vram_mib,min_cpu_cores. Endpoints must be deployment-approved; credentials resolved server-side. Pools use disjoint case-insensitive model IDs, not proof of distinct weights/digests. Never mix demo with real. A/B selection fixed for each stage/coding/chat unit, including reviews. Provider probes retain explicit lane checks. Queue fingerprint includes routing registry/policy; changes invalidate queued work rather than silently reroute. Fixed policy preserves legacy fingerprint.

Task classification uses department, kind and character-count heuristic; coding requires structured capability declaration and high complexity requires configured context >=8192; other tasks >=4096. Context and quality are declared estimates, not tokenizer or evaluated quality guarantees. Resource checks use backend-visible RAM/CPU and optional NVIDIA free VRAM on one device, not reservations or remote hardware. Unknown required metric excludes candidate. Candidate order deterministic: local first, zero-cost preference, specialty, then quality for high complexity or price and RAM for standard. General capability can cover specialty when no specialized option. Quality is operator declaration, not learned routing; no automatic model downloads or hidden fallback. Registry is read-only in Web UI and changed through deployment environment/restart. Remote and nonzero-cost candidates require ORBIT_ROUTING_ALLOW_REMOTE=1 and active exact endpoint/model rates both <= ORBIT_ROUTING_MAX_RATE_USD_PER_MILLION (default 0). Rate ceiling checked at pair selection, not a billing guarantee; rates may change before actual request and budget/circuit breaker P5.7 is separate. Loopback keyless non-cloud Ollama is an assumption of local zero API cost, not proof of network isolation. Fixed mode explicitly configured remote behavior unchanged. No retry with a different model after any inference call; no eligible pair blocks before sending. Existing format retries stay on chosen model.

Operator GET /api/provider/routing and POST /api/provider/routing/preview show registry and recent decisions and simulate metadata only (no inference or history write); project member GET /api/projects/{id}/routing reads project history. Decisions stored with run ID and model/provider IDs, exclusion reasons, no prompts/credentials. Logs limited to last 100 in view; storage not automatically pruned. Routing records persisted before calls; usage/cost records remain authoritative for actual requests. Fixed mode and demo also record decisions. Operator-only /routing.html via provider settings. Offline CI adds separate real two-model selection (reverses base pair, verifies remote excluded, actual routed requests and ledger); existing generation/repair and concurrency gates retained. No paid API live test, no model quality evaluation, no multi-GPU resource reservation, no production signoff.

Both pipeline and coding submissions bind the same registry fingerprint; a policy change blocks either before inference. The main dashboard labels smart routing rather than displaying fixed configured models as actual selections. Routing HTML itself requires operator authorization; project members can inspect their scoped decision API.
