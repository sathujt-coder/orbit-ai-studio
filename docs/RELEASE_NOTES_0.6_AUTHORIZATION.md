# P3.6 / P3.7 — Local HTTP authorization
Dashboard redirects unauthenticated users. Every existing business route goes through a default-deny allowlist; resource IDs resolve to actual project IDs, bootstrap is filtered, mutations require same-origin and session CSRF. Existing project access must be explicitly provisioned via local operator; authenticated users may create their own Web project and become its owner. Owner can grant developer/reviewer/viewer to existing users, cannot self-change or grant ownership. Read-only members and audit endpoints are owner-only. Audit records authorization decisions, not proof of operation success; CLI operations remain trusted local operator paths. No HTTPS or production readiness claim. Security Chromium test covers anonymous, cross-project, viewer mutation, elevation, missing CSRF and audit. Existing E2E tests now use real sessions.
