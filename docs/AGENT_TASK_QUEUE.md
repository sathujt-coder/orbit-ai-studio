# P5.4 — Agent Task Queue
/queue.html lists project-scoped persistent tasks and events, priority 0–9 (9 highest), FIFO ties, optional dependency on an existing same-project task. No dependency cycles (links only at insertion to older tasks); dependencies require succeeded queue execution, not separate production signoff. Pipeline retains ordered stage and human approval gates. One active queue item per project/kind, at most 200 active items globally. Single server dispatcher executes one pipeline stage or complete coding job at a time, with atomic coding job+queue insert. Pipeline all requeues at a stage boundary, waits for explicit approval/resume. Coding start and existing pipeline run routes submit to SQLite. Synchronous chat/probes and trusted CLI tools remain outside queue. No global inference concurrency claim until P5.5. Strict priority can starve low priority work; fairness future.

States queued/running/paused/waiting_approval/succeeded/dead/interrupted/cancelled; bounded history. Running pipeline pause/cancel at stage boundary only; running coding cannot interrupt. Retry is explicit, creates a new queue row/coding job, preserves past outputs/history, may consume more tokens; reset a failed stage using existing retry-stage control first. A failed dependency blocks its dependents; choose a new task when dependency did not succeed. Enforced resource pressure can cause at most two pre-dispatch deferrals (2 and 4 seconds), then dead letter; no automatic retry after any inference starts. Provider revision and nonsecret configuration fingerprint bound at enqueue, rechecked each dispatch. Credential rotation at same endpoint with same key presence is not fingerprinted; operator must manage credential changes. Original submitter write permission is rechecked at claim and before dispatch. A revocation during an active unit takes effect at next dispatch.

Linux/macOS server holds an advisory exclusive dispatcher file lock beside SQLite for lifetime; no distributed workers, Windows server not supported by this lock. On restart, queued and paused tasks remain; running tasks become interrupted, partial pipeline stage needs_revision, coding job failed; never blindly replay potentially billable work. Legacy in-flight tasks also marked interrupted. Recovery is startup-only with lock; uncertain storage failure stops worker until restart. Clean shutdown waits for current unit. No automatic execution of generated code or Git writes. Existing approval and sandbox gates remain mandatory. Offline benchmark integrates queue insertion, claim and finish around actual model calls using its trusted smoke-specific worker (not production scheduler), while Chromium exercises production dispatcher in demo mode. Production restart drill, actual multi-agent contention, fairness, distributed locks and load tests remain later.
