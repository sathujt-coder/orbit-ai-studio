# P3.5 account UI
Adds /account.html, a dashboard account link, login/logout, session restore on refresh, accessible error/status text and in-memory CSRF handling. No password/session token stored in localStorage. A test-only account is created in the temporary CI database. Chromium checks failed login, successful login, cookie attributes, refresh and logout. Existing business APIs and dashboard are still unauthenticated; this is intentionally not a security boundary. User administration remains CLI-only. P3.6 must enforce authorization across all routes; HTTPS, production rate limits and security review remain pending.
