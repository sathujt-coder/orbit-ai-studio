# P5.5 — Concurrency Control
Process-local shared limiter wraps all real inference through the server's tracked_chat path: pipeline, coding factory, agent chat, and operator probe. Metadata-only list/status endpoints retain their separate rate limits. Demo does not consume inference slots. Direct trusted CLI calls not using this limiter and other processes/services are outside its scope.

Startup policy: ORBIT_QUEUE_WORKERS=1 (1–8); ORBIT_INFERENCE_GLOBAL=1 (1–24); ORBIT_INFERENCE_ENDPOINT=1; ORBIT_INFERENCE_MODEL=1; ORBIT_INFERENCE_PROJECT=1 (scoped limits cannot exceed global); ORBIT_INFERENCE_WAITERS=32 (0–128); ORBIT_INFERENCE_WAIT_SECONDS=30 (0–600, zero rejects immediately). Set e.g. workers=2, global=2, endpoint=1, model=1, project=1 to overlap separate endpoints without overloading one Ollama. Endpoint identity is scheme + normalized hostname + effective port (loopback aliases grouped), not provider/credential/model/API path. DNS aliases, proxies and external clients may still share physical capacity; limits are not provider-side hardware guarantees. System probes share a project-like bucket. Model limit applies to exact model ID per endpoint.

Admission is atomic under a condition variable; eligible FIFO with blocked-endpoint bypass; bounded waiters and deadline; no DB lock while waiting. Recheck RAM after acquiring a slot; only then commit token/cost start. Release on success, transport failure, resource refusal, DB failure. Refused chat returns HTTP 429 without inference ledger entry; probes report failed; queued work failing during a unit is not blindly replayed. No per-token streaming or hard wall-clock cancellation of provider requests; slot held through transport and ledger completion. Shutdown wakes waiting inference calls and waits for queue workers. Process-local counters reset on restart.

One exclusive dispatcher process per DB remains, now with fixed worker pool; database claims exclude any other running task in the same project and a partial unique index enforces this. Different projects may overlap; pipeline stages and A/B drafts/reviews within a unit remain sequential. Chat can overlap workflow if policy permits, but project inference cap applies. Storage fault stops new claims and health reports unavailable. Existing recovery/approval gates preserved. No distributed semaphore, dynamic GPU reservation, per-agent priority inference scheduler or 24/7 stress claim.

Operator resource API and dashboard show configured limits, live slots/waiters, peaks and counts; project queue exposes only aggregate worker capacity. Tests cover actual simultaneous local HTTP fixture requests, timeout/full queue, exception cleanup, endpoint aliases, ledger exclusion, real worker threads across projects and same-project serialization. Offline CI preserves default single-slot generation/repair gate and adds separate three-request real Ollama client contention benchmark with limit two. Ollama itself remains configured for one parallel generation and one loaded model under 6 GiB/2 CPUs; peak client slots does not prove GPU parallel execution. Production hardware and sustained load deferred.
