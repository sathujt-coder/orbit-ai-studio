# Defect assignment and repair tracking

Append-only event receipts are keyed by project, job, finding and exact detected registration digest. Each new registered occurrence gets a separate chain. Recovery does not implicitly change any receipt. Only an active project reviewer/owner may assign, reassign, reject, verify or close. Assigned active developers/owners may start and submit. Self-review and same-reviewer closure are forbidden. No agent dispatch, model calls, execution authorization or gate override occurs.

GET/POST /api/projects/{project}/engineering/defect-repairs/{job}: POST uses exact current view digest, explicit action confirmation and current membership in a BEGIN IMMEDIATE transaction. Submission binds a fresh trusted execution, candidate and regression digest. Verification and explicit independent closure additionally require current full regression PASS and the original assertion identity passing; changed or removed assertions are not accepted as proof. A rejected repair returns to IN_PROGRESS. Registry history remains immutable even after tracking closure.

The Studio coding-job panel exposes the history and explicit commands. CI exercises the trusted Docker failure/recovery fixture over HTTP, including rejection of changed assertion verification, and unit regressions for receipt transitions, authorization and audit rollback. Development evidence only; no production or model acceptance.
