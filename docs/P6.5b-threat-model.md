# P6.5b — Threat Modeling & Security Requirements (development only)

Architecture baseline: seven assets, six trust boundaries, all six STRIDE categories, 16 identified threat scenarios and 16 mandatory one-to-one security requirements. Severity is a conservative architecture-level priority, not a measured vulnerability or residual risk. Each requirement has a verification method ID for subsequent implementation (SAST, DAST, dependency/secret scanning, sandbox, audit, transport and release controls). No threat is declared mitigated. The baseline does not analyze the actual candidate's features, data flow or custom dependencies; project-specific modeling and independent review are future work.

GET /api/projects/{pid}/engineering/threat-model/{jid} is scoped read-only and rechecks current membership in a transaction. The model binds exact current P6.5a evidence, selected candidate, plan, execution, regression and retest digests and policy; catalog is independently hashed. Current source absent or invalid evidence blocks. THREAT_MODEL_READY means only baseline inventory bound to current evidence; all requirements remain NOT_VERIFIED, risk UNASSESSED, candidate analysis NOT_ASSESSED and security gate BLOCK. No write/approval route, no new DB table, no production transition, no automatic authority. Dashboard uses manual refresh, textContent and clears old snapshots on job/project/repair changes.

Sixteen unit regressions, real HTTP owner/viewer and denial checks, three isolated checkpoints derived from the existing actual Docker runs. CI independently reconstructs models from exact security snapshots, checks six checkpoint states and traceability, and publishes mandatory run-bound engineering-threat-model-evidence.json. Studio independently hashes downloaded bytes and requires the security and retest links in addition to all prior gates. No model, prompt, token budget, inference limit, production gate or CI deadline changes. No paid services.

One additional controlled-response Chromium regression verifies READY remains security BLOCK, requirements NOT_VERIFIED, foreign scope rejection, and late response discarded on a job switch. Real HTTP remains covered separately by the planning fixture.
